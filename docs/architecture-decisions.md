# Architecture Decision Records (ADRs)

## 1. Modular Monolith over Microservices
**Context**: The manufacturing platform has 12 distinct domains (PDM, BOM, Inventory, Production, CRM, SCM, etc.). A microservices architecture was considered.
**Decision**: We chose a Modular Monolith.
**Reasoning**: Microservices introduce extreme operational overhead, distributed transaction failures, and complex CI/CD pipelines. A modular monolith enforces boundary separation at the package level while allowing in-memory, transactional consistency (crucial for ERP/Inventory operations) and vastly simpler deployments. 

## 2. PostgreSQL + pgvector
**Context**: We need a highly reliable transactional SQL database and a vector database for AI-driven RAG queries on engineering documents.
**Decision**: PostgreSQL with the `pgvector` extension.
**Reasoning**: Eliminates the need to synchronize data between a relational DB and a separate vector DB like Pinecone/Milvus. It allows us to perform hybrid queries (e.g., `SELECT semantic_similarity AND status = 'ACTIVE'`) with perfect ACID compliance.

## 3. Role-Based Access Control (RBAC) via Spring Security + JWT
**Context**: Users span Executives, Sales, Engineering, Procurement, and Production, requiring strict scope-level authorization.
**Decision**: JWT (JSON Web Tokens) generated by Spring Security.
**Reasoning**: Stateless authentication allows horizontal scaling. Spring Security `@PreAuthorize` annotations bind security rules directly to API contracts, ensuring endpoints cannot be bypassed. 

## 4. Grounded AI (No Unrestricted Database Access)
**Context**: Generative AI is required to answer operational queries, posing severe data leakage and hallucination risks.
**Decision**: AI is implemented via a strict RAG (Retrieval-Augmented Generation) pattern. The LLM never has SQL access.
**Reasoning**: Users ask queries -> Java Backend intercepts -> Backend checks user roles -> Backend retrieves *only* authorized data -> Backend injects bounded context into the prompt -> LLM synthesizes. This entirely mitigates SQL injection and cross-tenant data leakage.

## 5. Next.js App Router for Frontend
**Context**: An enterprise-grade frontend is required for multiple dashboards.
**Decision**: Next.js 14 with React and Tailwind CSS.
**Reasoning**: Next.js provides severe performance benefits (Server Components), built-in routing, and a massive ecosystem of enterprise-ready UI frameworks.
